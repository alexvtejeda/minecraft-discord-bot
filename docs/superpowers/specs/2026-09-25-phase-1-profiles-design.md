# Phase 1: World profiles — Design

Date: 2026-09-25
Status: Approved design
Parent design: [2026-09-25-minecraft-discord-bot-design.md](2026-09-25-minecraft-discord-bot-design.md)

## Goal

Describe a world's whole setup in one small file that lives in the repo. The file covers
the Minecraft version, the Fabric loader, the mods and which side each runs on, the
datapacks, the resource pack and `server.properties`. From that file, the tooling builds
two things:

- a runnable Fabric server folder
- a `.mrpack` that friends import into Prism Launcher with one click

Two kinds of world must both work:

- **Vanilla+:** server-side mods only, so vanilla clients can join.
- **Themed modpacks:** every player needs the pack to join.

## Decisions

| Topic | Decision |
|---|---|
| Profile source | JSON files in `profiles/`, committed. `/world new <name> <profile> [seed]` (Phase 3) picks one. `/mod add` still adds one-off extras to a running world. |
| Reproducibility | A committed lockfile, `profiles/<name>.lock.json`, generated by `profile resolve`. Updates show up as reviewable diffs. |
| Mod source | Modrinth references. Jars that exist only in R2 (from `/mod add`) are supported in later phases. |
| Datapacks and resource packs not on Modrinth | Uploaded once by a maintainer (`/pack add`, Phase 3) and stored privately in R2. Never committed, because Vanilla Tweaks doesn't allow redistribution. |
| Resource pack delivery | Pushed by the server through `server.properties`. The Worker serves it at a permanent URL based on its hash (Phase 2). It's optional unless the profile sets `require: true`. |
| Client delivery | `.mrpack`, which Prism Launcher and the Modrinth App import natively, from a file or a URL. Optional mods appear as a checklist. |
| Unavailable mods | The profile's `waiting` list. Resolving skips these mods and reports when they become available. |
| Target version | 26.3, which needs Java 25. Fabric loader 0.19.5 and installer 1.1.2 at the time of writing. |

## Profile format

```jsonc
// profiles/<name>.json
{
  "name": "adventure",
  "description": "Structures, storage and QoL. Everyone needs the modpack.",
  "minecraft": "26.3",
  "loader": { "fabric": "latest-stable" },      // or an exact version
  "memory": { "min": "2G", "max": "4G" },
  "properties": { "difficulty": "normal", "view-distance": 10, "simulation-distance": 8 },
  "mods": [
    { "modrinth": "lithium", "side": "server" },
    { "modrinth": "waystones", "side": "both" },
    { "modrinth": "simple-voice-chat", "side": "both", "clientOptional": true },
    { "modrinth": "travelersbackpack", "side": "both", "version": "26.3-11.4.0" },
    { "modrinth": "sodium", "side": "client-optional", "default": true }
  ],
  "waiting": ["lootr", "carry-on"],
  "datapacks": ["vt:afk-display"],
  "resourcePack": { "pack": "vt:resources", "require": false }
}
```

### Sides

| `side` | Installed on server | In `.mrpack` |
|---|---|---|
| `server` | yes | no |
| `both` | yes | `env.client = required`. With `clientOptional: true` it becomes `optional` instead. |
| `client-optional` | no | `env.client = optional`, unticked unless the mod is marked `default: true` |

A profile counts as Vanilla+ when no mod is `both` without `clientOptional`. `/modpack`
uses this to tell players whether the pack is required (Phase 3).

### Lockfile

`profiles/<name>.lock.json` is generated and committed. It pins:

- the Minecraft version, and the Fabric loader and installer versions
- for each file: the Modrinth project and version IDs, filename, URL, sha512, sha1, size,
  side, `clientOptional`/`default`, and flags `auto` (pulled in as a dependency) and
  `prerelease`

The same inputs always produce the same lockfile: entries are sorted, and the file contains
no timestamps.

## Starter profiles

### `vanilla-plus` (default)

- **Server:** Fabric API, Lithium, FerriteCore, C2ME, ScalableLux, VMP, Chunky, spark.
- **Both (client optional):** Simple Voice Chat.
- **Client-optional:** Sodium, Iris, ImmediatelyFast, EntityCulling, Mod Menu, AppleSkin,
  Jade, Xaero's Minimap, Xaero's World Map.
- **Datapacks:** the group's Vanilla Tweaks set, updated to 26.3. Resource pack:
  Vanilla Tweaks resources.

### `adventure` (26.3, modpack required)

- **Server:** Fabric API, Lithium, FerriteCore, C2ME, ScalableLux, VMP, Chunky, spark,
  Universal Graves (replaces Gravestone), Skin Restorer, Villager Config, Dungeons and
  Taverns, Incendium, Nullscape, Towns and Towers.
- **Both:** Bartering Station, Clumps, Easy Anvils, Nature's Compass, Storage Drawers,
  Tom's Simple Storage, Trade Cycling, Traveler's Backpack, Waystones, Underground
  Villages, Hammers and Excavators (`hammers-and-excavators-miners-dream`), and Simple
  Voice Chat (client optional).
- **Client-optional:** Jade, JEI, Xaero's Minimap, BadOptimizations, Sodium, Iris.
- **Waiting:** Lootr, Carry On, Explorify, Nether Chested, Refurbished Furniture,
  Spiral Tower Villages, Medieval Buildings, True Ending.
- **Dropped (no usable Fabric version):** SecurityCraft, Aquaculture 2, AirHop, Goblin
  Traders, Sophisticated Backpacks.
- **Datapacks and resource pack:** the same as `vanilla-plus`.

Exact sides come from checking each mod's Modrinth `client_side`/`server_side` metadata
during implementation. The lists above are the starting point.

Structure mods added to a world later (from `waiting`) only affect chunks that haven't been
generated yet, so worlds are pre-generated only to a modest radius (Chunky, 2,000 blocks by
default).

## Network change

Simple Voice Chat uses UDP 24454. `infra/tailscale/policy.hujson` adds `udp:24454` to the
grant between `tag:mc-player` devices, and a policy test covers it.

## Code layout

A Bun workspace:

```
packages/profile/   schema, resolver, server builder, mrpack builder — pure TS, no CLI
apps/agent/         mc-host. Phase 1 only adds the `profile` subcommands.
profiles/           *.json and *.lock.json
```

The profile package takes a fetch function and a cache directory as parameters, so the
Worker can reuse its schema and mrpack builder in Phase 2 and Phase 3.

## Commands (Phase 1)

### `mc-host profile resolve <name> [--check <mc-version>] [--add-ready]`

1. Validate the profile and give plain-English errors.
2. For each mod, choose the newest Modrinth version for the profile's Minecraft version
   and Fabric. Prefer `release`. Fall back to `beta` or `alpha` with a warning and a
   `prerelease` flag. Respect a `version` pin.
3. Resolve required dependencies recursively and mark them `auto`. A dependency inherits
   the side of the mod that needs it. If several mods need it, the widest side wins:
   `both` beats `server`, and `server` beats `client-optional`.
4. Fail if the Modrinth metadata declares an `incompatible` dependency between two mods.
5. Write the lockfile.
6. Check each `waiting` mod and report which ones now have a build.
   - `--add-ready` moves the ready ones into `mods`, using the side from their Modrinth
     metadata.
   - Mods that run on both sides go in as `both`. Mods that run only on the client go in
     as `client-optional`.
7. `--check <version>` prints an availability report for another Minecraft version
   without writing anything.

### `mc-host profile build-server <name> <dir>`

- Download the Fabric server launcher jar from
  `meta.fabricmc.net/v2/versions/loader/<mc>/<loader>/<installer>/server/jar`.
- Download the `server` and `both` files into `mods/`.
  - Check each file's sha512.
  - Cache files in `~/.cache/mc-host/` (or `%LOCALAPPDATA%\mc-host\cache`), keyed by hash.
  - Remove any jars in `mods/` that the lockfile doesn't list.
- Write `server.properties` from the profile, on top of Minecraft's defaults.
- Copy datapacks into `world/datapacks/`, but only when `world/` doesn't exist yet. In
  Phase 1 they come from a local folder (`--packs <dir>`); from Phase 2 they come from R2.
- The EULA is never accepted automatically. `run` asks for it once and remembers the answer.

### `mc-host profile build-mrpack <name> <out.mrpack>`

- `modrinth.index.json`:
  - `formatVersion: 1`, `game: minecraft`, `versionId` = the lockfile hash
  - `dependencies`: the Minecraft and Fabric loader versions
  - `files`: each file with its Modrinth CDN URL, sha1, sha512 and size
  - `env`: set according to the Sides table; `server` files are left out
- Jars that exist only in R2 go in `overrides/mods/`.

### `mc-host profile run <dir>` (Phase 1 local testing only)

- First run: show Mojang's EULA URL and require the user to type `yes`. The answer is
  saved in the agent's config, and then `eula.txt` is written.
- Run `java -Xms<min> -Xmx<max> -jar fabric-server-launch.jar nogui` in the foreground.
- Check the Java major version first. 26.3 needs Java 25.

## Error handling

Every error is in plain English and says what to do next.

| Situation | Behavior |
|---|---|
| Unknown Modrinth slug | Fail, and suggest the closest search result. |
| A listed mod has no build for this version | Fail, and suggest moving the mod to `waiting`. |
| Only prerelease builds exist | Continue, with a warning and a `prerelease` flag in the lockfile. |
| Incompatible mods | Fail and name both mods. |
| A dependency isn't on Modrinth | Fail, and suggest `/mod add` (Phase 3) or dropping the mod that needs it. |
| sha512 mismatch | Retry once, then fail. The file is never placed in `mods/`. |
| Modrinth down or HTTP 429 | Retry with exponential backoff, respecting the `X-Ratelimit-Reset` header. Then fail with a "try again in a few minutes" message. |
| Wrong Java version | "26.3 needs Java 25, found N." Phase 2 downloads the right JDK automatically. |
| Server crashes on boot | Print the last 30 lines of the log and name the suspect mod from the crash report, if it can find one. |

All Modrinth requests send
`User-Agent: alexvtejeda/minecraft-discord-bot/<version> (github.com/alexvtejeda/minecraft-discord-bot)`.

## Testing

- **`bun test` in `packages/profile`,** using saved Modrinth and Fabric meta responses and no
  network. It covers:
  - schema errors
  - version selection: release preferred, prerelease fallback, pins
  - dependency resolution: side inheritance, loops, incompatibility
  - `waiting` reports and `--add-ready`
  - the Sides-to-`env` mapping
  - the `.mrpack` index contents
  - that the same inputs always give the same lockfile
- **`bun test --live`** (manual): resolve both real profiles against the live APIs.
- **Manual checklist** (this is Phase 1's "done when"):
  - [ ] `vanilla-plus` and `adventure` both resolve, and their lockfiles are committed.
  - [ ] `adventure` builds and boots on Fedora with Java 25.
  - [ ] The `adventure` `.mrpack` imports into Prism, and the player joins `localhost`.
  - [ ] A vanilla 26.3 client joins `vanilla-plus`.
  - [ ] The voice chat policy change is saved and its test passes.

## Out of scope for Phase 1

- The R2 and Worker side: storing and uploading packs, serving the resource-pack URL, and
  `/world new`. These come in Phases 2 and 3.
- Portable JDK download (Phase 2).
- Modrinth modpack or CurseForge sources.
- Automatically placing mod config files. Mod defaults are used. An `overrides/config/`
  folder per profile is a possible later addition.
